# Phase 2 external validation protocol

**Status.** Proposed preregistration for a bounded feasibility study on human-written C++ programs. Freeze the sampling and screening rules before screening. The Phase 1 pilot supplies development evidence and a fixed comparison recipe.

## Research question and sampling

Does slice-constrained Abstract EAPG improve localization over the Phase 1 deterministic ranker on held-out competitive-programming problems? The primary contrast is paired Top-1 on independently confirmed scaling regressions with adjudicated reference nodes, with equal weight per quarantined group. Coverage, false alerts on negative controls, and performance on multi-candidate slices are separate outcomes.

- Use the human-written C++ pairs in the official PIE test release, reported as 978 pairs across 41 problems. Treat the runtime metadata as provenance and establish scaling evidence and localization references independently. Pin the release, file hashes, usage terms, problem IDs, both submission identifiers or source hashes, and test indices. The validation split is outside this study's sampling frame. [PIE paper, §2](https://arxiv.org/html/2302.07867v5#S2) · [Official dataset documentation](https://github.com/LearningOpt/pie#dataset)
- Visit every problem in the pinned test split in seed-42 shuffled order after sorting the problem IDs. Within each problem, keep the first pair in stable pair-ID order for each canonical slow-source key. Sample up to four of those representatives without replacement. A later fast edit for the same slow program cannot consume another draw or replace a screened pair. The published frame allows at most 164 draws. Freeze the full draw before compilation, profiling, or reference review. Retain every draw in the screening ledger and complete the draw regardless of how many positives qualify. Any broader confirmatory frame requires a separate preregistration.
- For each sampled problem, nominate at most one accepted C++ negative control from the same release. Exclude submissions matching any drawn slow submission ID or canonical slow-source key for that problem. Use stable hash order among submissions whose existing algorithm two independent reviewers judge to meet the problem's known asymptotic bound on the registered workload. Verify outputs and count missing or indeterminate controls. Keep verified negatives separate from constant-factor and inconclusive PIE pairs.

## Test custody and quarantine

Before training, a custodian groups the proposed train, validation, and test examples, including pilot rows. Connect shared problem IDs or known aliases, repeated submissions, exact normalized source, either side's identifier- and numeric-literal-normalized AST, and identical final tokenized inputs. Freeze the fingerprint definitions and parse-failure fallback. Keep each connected component in one split. Give test groups precedence and remove conflicting development rows. Halt on remaining problem-ID or fingerprint overlap. Publish any pilot training rows removed and use the same remaining rows for all neural baselines. Synthetic mutations originate from training problems only.

Seal the split manifest with hashes, problem and group IDs, submission counts, RNG version and seed, and labels and exclusions once available. Reviewers see test specs, both submissions, and independent profiling evidence. They remain blind to EAPG candidates, prompts, predictions, and variant-specific scores. The models receive the slow program and registered inputs, plus slow-side features where the variant calls for them. The custodian holds fast programs and reference labels separately and opens them for scoring after predictions and run hashes are sealed.

## Safety and eligibility gates

**Execution.** Run all external preprocessing, static Pass 0–2 map extraction, compilation, and execution inside the disposable isolated guest or container. This includes both GCC preprocessing passes. Use no network, host credentials, or host filesystem mounts. Run as an unprivileged user with a read-only root, bounded scratch storage, and hard process, CPU, wall-clock, memory, and file-size limits. Bound captured output during reads, feed stdin through a pipe or file, and kill the process tree on timeout or crash. Demonstrate enforcement with locally authored quota-exhaustion probes before opening external code. Freeze the tested compiler, flags, sandbox image digest, and limits. Log compile failures, tick caps, timeouts, resource-limit events, sanitizer findings, crashes, and output mismatches separately. Retain EAPG's instrumentation ceiling as an additional bound, and exclude capped runs from fits. [Phase 1 audit of the existing wrapper](../board_of_audit_professors.md)

**Profiling records.** Register a once-only normal-exit handler at instrumented `main` entry and keep a separate tick-cap record path. The normal handler must return after emission. Test an early return from `main`, a helper calling `std::exit(0)`, tick caps, and abnormal exits. Reserve a bounded counter channel separate from stdout and stderr, such as FD 3 inside the guest. The supervisor records process exit and resource-limit status independently and validates record count, size, schema, and counter consistency before fitting. Code in the instrumented process can also write to its inherited descriptor. Treat its counters as in-process telemetry and require a separate trust mechanism for adversarial counter integrity.

**Workload and reference.**

1. Before looking at test results, register a valid size-parameterized generator and independent output checker per problem from its specification. Freeze the size definition, constraints, input distributions, seeds, timer-resolution rule, and scaling grid. Retain available official tests. Aim for at least four geometrically spaced sizes spanning an eightfold range, three fixed input seeds per size, and five independent timings per seed and program at the pinned -O2 build. Randomize execution order using the registered seed. Check outputs on every profiled input, including plain versus instrumented results when profiling completes, and run supported undefined-behavior checks on the same inputs. Oracle failures and undefined arithmetic invalidate a scale.
2. Confirm a positive with independent evidence of a scaling change. Two reviewers verify the slow and fast algorithms and their expected growth on the registered workload. Require a log-log slope of median slow/fast runtime ratios of at least 0.5 for each input seed and a slow/fast ratio of at least 1.5 at the largest size for each seed. This screens for a growing ratio over the measured range. Require at least four usable sizes spanning the registered range. Record a constant-factor case only when code review supports the same growth class. Use an indeterminate label if measurements are insufficient, conflict with code review, or fail the output oracle. Validate the screening rule on development cases and lock it before inspecting test timings.
3. Have two reviewers independently mark causal spans in the raw slow source and explain how they affect scaling. Preserve their initial spans before node mapping. Give them both raw submissions and a static Pass-2 map of the slow program with node IDs, AST roles, and source spans. The map must come from the exact normalized source used for scoring and contain no counters, fitted exponents, prompts, rank tags, or slice membership. Distinguish normalized-source offsets from raw-source locations. Record macro expansion origins and synthetic braces where the mapping can be verified. A third reviewer adjudicates ambiguous mappings or disagreements using static evidence before scores are opened. Preserve the mappings, the accepted reference set, and unresolved or nonlocalizable cases. A Top-1 hit is any accepted node and candidate recall is nonempty intersection with the reference set.

For generated scaling workloads with a test-case count `t`, fix `t=1` when the specification permits a single independent case and the workload of interest varies its size. Use the same valid input bytes for both versions. If the workload depends on multiple cases or aggregate constraints, register a different fixed legal `t` or a joint scaling rule and record what varies. Preserve the original official tests for correctness. Fit the parent exponent from its measured counters. A fixed case count controls loop iterations when the case loop simply iterates over cases.

## Comparison and reporting

- Compare the work symptom, raw slice order, and refined deterministic ranker with binary-tagged Abstract EAPG as the primary trained variant. Secondary variants include Lexical EAPG, full-source models, and matched 26-character preview models. Score common candidate sets with and without the same slice mask, and identify which prompts expose slice or rank tags. Match backbone, tokenizer, adaptation budget, training rows, and predeclared seeds. Fit fresh adapters once on quarantined pilot development rows with the locked Phase 1 recipe and label the resulting model as external transfer from pilot training. Lock thresholds, context and node-ID limits, truncation, and abstention rules on development data. Record unsupported source, node IDs, and context limits as failures. Reserve learning curves and training on human-written examples for a separate experiment with an untouched test cohort.
- **D_pos — End-to-end.** Use all adjudicated positives for the primary paired Top-1 contrast. For each method, score missing symptoms, empty slices, reference misses, unsupported encodings, and abstentions as misses where they prevent that method from returning the reference. The symbolic ranker can still score cases that exceed the neural limits. Report each method's coverage as the proportion of D_pos with a valid ranked output.
- **D_elig — Representation-eligible end-to-end.** Within D_pos, use the common subset whose slow program has at most 26 macro-nodes and whose exact frozen binary-tagged Abstract prompt fits in 512 tokens including one reserved answer token. Use Qwen2.5-Coder-1.5B tokenizer revision `df3ce67c0e24480f20468b6ef2894622d69eb73b`, with no truncation. Determine eligibility without reference labels. Record unmeasurable prompt lengths separately. Where the prompt can be serialized, retain missing symptoms and empty slices as end-to-end misses.
- **D_rank — Multi-candidate ranking.** Within D_elig, use pairs for which the frozen selector actually emits a slice with at least two candidates. Both rankers score the same candidate set. A slice that omits every accepted reference counts as a miss for both. An all-node fallback for an empty slice does not count as an emitted slice. Report candidate recall and singleton counts separately.
- D_elig and D_rank use Abstract EAPG eligibility for the primary pair of methods. For every neural variant, log the actual prompt token count, required answer tokens, applicable cap, and whether tokenization or node encoding failed. Summarize variant-specific context overflow, unavailable prompts, and valid outputs within D_elig and D_rank. Secondary rows on these cohorts retain the same denominators and count variant-specific failures as misses. For a paired representation comparison, also report the intersection where both variants can score under the same decoding restriction. Label this intersection and give its pair and group counts.
- Report the screening flow from drawn pairs through compilation, output checks, sufficient scales, confirmed regression, adjudication, symptom, slice, and ranked output. Give pair and group counts for each denominator and report Top-1 and Top-2. Give a conservative lower-bound accuracy over confirmed positives by counting unresolved references as misses. Report false alerts on verified negatives and describe constant-factor and indeterminate cases separately.
- For the primary contrast on D_pos, average paired Top-1 differences within each group and weight groups equally. Report pair-weighted results, discordant groups, a 95% paired bootstrap interval over whole groups (10,000 draws, seed 42), and leave-one-group-out sensitivity. Use D_elig and D_rank as secondary analyses. Fewer than 20 groups in D_pos, or a primary interval including zero, yields insufficient evidence of a positive transfer advantage. The full draw is a feasibility budget. Limit claims to the sampled frame and workloads, and disclose potential base-model exposure to public submissions.

## Root-scope diagnostic

Use the frozen Phase 1 selector (`v1.0-frozen`) in the primary tables. It assigns a zero parent-relative jump when a loop's parent is unprofiled `MAIN_SCOPE`. A flat polynomial loop directly under `main` with equal hit and work exponents can therefore fail to emit a symptom. Record that pattern in the failure ledger. [Frozen selector](../../pipeline.py#L2342)

Register a separate diagnostic (`v1.1-root0`) before scoring. For a polynomial loop directly under unprofiled `MAIN_SCOPE`, set the parent work exponent to zero when computing the relative work jump. Hold all other thresholds, rules, traces, and inputs fixed. On D_pos, report how many frozen missing-symptom cases gain a symptom and how many gain a slice containing an accepted reference. On verified negatives, report additional false alerts, including on ordinary linear loops. Keep diagnostic counts separate from the primary ranking and accuracy results.

The frozen work selector builds the qualifying list in macro-node traversal order. It chooses the first qualifier that is a hidden-work node, loop, or function entry. If none has one of those properties, it uses the first qualifier. The diagnostic preserves that ordering. A qualifying linear input loop can therefore displace a later quadratic solver. Log the ordered qualifiers and selected node for both runs. On D_pos, also report how often an existing frozen symptom changes and whether reference coverage changes from zero to at least one accepted node or the reverse. [Frozen selection loop](../../pipeline.py#L2377)
