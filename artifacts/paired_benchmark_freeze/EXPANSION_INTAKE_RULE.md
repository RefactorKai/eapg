# Expanded intake rule

This rule fixes the scrape only, not desk assessment or the analysis. The frozen protocol is pinned by SHA-256 `8a9692457cdba6d9b2860717b8bc254dae47dc48eebe7baacabb17a82007953e`.

- Retain the 500 original validation rows as the development-exposed stratum. Neither those rows nor any new cluster connected to the archived study contributes to the confirmatory target.
- Take up to 100 Repository clusters from a bounded GitHub search snapshot. Use the first 100 repositories from `language:C++ stars:>=1000 archived:false fork:false is:public`, by stars descending; break returned ties by case-folded name. In alphabetical batches of ten repositories, request one page of 100 results for `"fix performance" committer-date:2020-01-01..2025-12-31 merge:false` plus the fixed repository qualifiers, descending committer date. The initially attempted unscoped search was rate-limited and too sparse in C++; the published PerfMiner sample hides repository URLs, and the PcMiner archive was inaccessible from this VM. This repository-first rule is frozen before reviewing any of its matched code, outcomes, or suitability. In the snapshot require the exact phrase as contiguous words (case-insensitive) in the subject, a single parent, and a recognized SPDX project license. The after side is the self-described repair commit and the before side its parent, not a measured ordering. Forks and redirects resolve to the upstream root; retain original pins for retrieval. Record license and full before/after bytes at changed C++ paths, including headers. Do not use speed measurements, build metadata, or execution promise for ranking.
- Repository breadth expansion: retain page 1 and add pages 2–5 of the same repository query, with the same within-page batching and commit query. Page 1 had only 17 repositories meeting the metadata filters, so it cannot meet the minimum even before intake. Do this expansion once, before selecting pins or retrieving any before/after source files. Keep all accepted pages and batch snapshots bound to the draw by hashes.
- Fill the remaining 500-slot extension with one Contest pair per distinct problem (including IBM's known problem aliases), alternating between PIE train and CodeNet, and skipping problem clusters already drawn. If a corpus runs out, give its unused slots to the other corpus. Consult only the public train and validation releases, never the test release.
- For CodeNet, restrict the problem allowlist to PIE train problems: PIE splits by problem, so no test split metadata is needed. Derive candidate pairs from same-author, accepted C++ submissions for the same problem and original compiler language, ordered chronologically with a strictly lower, positive recorded judge CPU time on the later submission. Use consecutive accepted submissions after grouping by author and compiler language; exclude candidates using either side of any publicly released PIE train or validation pair. The labels are judge metadata, not reproduced speed measurements.
- Order clusters lexically by the tuple (SHA-256 of compact UTF-8 JSON `["eapg-expansion-v1", corpus, cluster_id]`, cluster ID). Within clusters order pairs by the protocol's SHA-256 of compact UTF-8 JSON `["eapg-expansion-v1", corpus, cluster_id, pair_id]`, then lexical ties. Use the same pair ordering for the primary representative after overlap grouping, using the final component ID. Draw identities before retrieving or fingerprinting source bytes. Keep failed retrievals, unavailable license evidence and duplicates in the intake flow; do not replace rows because of any finding about code or runnability.
- Build connected components over judge/problem aliases or repository roots, normalized source, and identifier- and literal-normalized C++ template hashes. Include archive keys and connect across frames. Quarantine every component touching the archive; record direct collisions by key and report component counts by frame and distinct union. Never treat missing fingerprint coverage as proof of no collision.
