# Localizing changes that make C++ loops repeat work

Research design memo · 18 November 2026 · starting artifact `a4fe32b` · proposed study, before registration

**Decision.** Keep EAPG's question about the inexpensive statement that makes another statement expensive. Give the investigator both program versions, the same workload, and a fixed inspection budget. Ask whether explaining *where a traversal loses previously accumulated progress* helps identify an independently verified responsible change. Start with this mechanism because it yields a checkable prediction in units of work. Generalize only when a second mechanism supplies its own prediction and independent evidence.

The immediate deliverable is a logical model and a way to disprove its value. The existence claim is established below. A useful advantage on human changes, a sufficient supply of cases, public re-execution, and a publishable new contribution each require separate evidence.

## 2. The question and its proof obligations

**Target user and unit.** An engineer has two comparable revisions of a deterministic C++ computation, a common output contract, and a family of workloads indexed by size and shape. They want to know which changed source region to inspect first. Orient the pair as target and reference before profiling. Record whether it is a historical regression, an optimization read in reverse, or an independently authored solution. The last category can support a comparison of algorithms. It enters edit localization only when the change units and a valid local intervention can be established.

**Information boundary.** Every paired method sees both revisions, workloads, execution budget and a canonical diff. A changed unit is a maximal contiguous run of changed executable statements in the same lexical block, delimited by unchanged executable statements or block boundaries. Pair corresponding replacements across versions and anchor a reference-only deletion at the target gap. Exclude comments and formatting. Freeze ambiguous mappings as such before predicting. A method returns one unit and its evidence, or abstains. Intervention outcomes, reviewer labels, commit messages and issue explanations are withheld until scoring. Engineers may consult these sources separately when establishing provenance.

**Primary research question.** Among independently confirmed, multi-unit changes, does adding the measured loss of progress and its source dependence path improve first-inspection success over a paired change-impact ranker with identical inputs and budget? Count each change pair once per independent group in the confirmatory comparison. Include non-cursor mechanisms in the drawn population and report where the method abstains. Also report the prespecified cursor-mechanism stratum. A claim specific to that stratum needs independent labels and its own precision assessment.

**Proposition 1 — a missing comparator cannot be recovered from a target trace.** Let the observed input be target program T and all its runs on workload W. Choose a reference with smaller growth and a second reference with the same growth as T. The input to any target-only decision rule is identical in the two comparisons. A deterministic rule must misclassify at least one. A randomized rule has expected error at least one half under equal weights for these two comparisons. This is an identifiability result for the comparative question. A single-version tool can still estimate the growth of a named event.

**Proposition 2 — a statement with linear execution count can cause quadratic work elsewhere.** Given a sorted array and nondecreasing query keys, return the count of elements no larger than each key. A cursor may carry its previous position or restart at zero before each query. Both compute the same ranks because successive answers never decrease. Let the ranks be f₁,…,fₙ with f₀=0. The carried scan takes Σ(fᵢ−fᵢ₋₁)=fₙ advances. The restarted scan takes Σfᵢ. The excess is exactly Σᵢ₌₁ⁿ⁻¹ fᵢ. On array and queries 1,…,n, these totals are n and n(n+1)/2. The reset runs n times. Reading inputs and emitting ranks adds linear work to both versions in the unit-cost model.

| n | Carry advances | Restart advances | Excess explained by the reset |
|---:|---:|---:|---:|
| 4 | 4 | 10 | 6 |
| 8 | 8 | 36 | 28 |
| 16 | 16 | 136 | 120 |

**What the engineer would see.** Add a second changed statement that writes an unrelated diagnostic counter once per query. Both changed statements have n hits. The inner scan dominates the profile. Only the reset supplies the next scan's entry position. At n=8, tracing that value to its reaching definition and summing the discarded positions gives 28, exactly the excess. Restoring carry keeps every answer and removes those 28 advances. Restoring the irrelevant counter leaves all 36 advances. This is a multi-edit example with a discriminating observation and a check independent of the ranking score. It does not establish a win over a competent dependence slicer, which can solve this example too.

**A harder head-to-head example.** Give odd and even queries separate changed entry assignments. In the reference both carry the previous rank. In the target the odd assignment restarts at zero and the even assignment steps back one position. At n=16 each assignment executes eight times and reaches eight scan entries. The unweighted reaching-definition vote ties. Odd queries lose 0+2+…+14=56 positions and even queries lose eight. The target takes 16+56+8=80 advances. Restoring only the odd assignment removes 56/64 of the excess (87.5%). Restoring only the even assignment removes 8/64 (12.5%). Both changes matter and one accounts for seven times as much work. A competent paired ranker that weights reachable extra advances also selects the odd assignment here. This makes the latter the decisive competitor. The accounting identity alone supplies no superiority theorem.

**A separating prediction for the primary comparison.** Return to the all-restart example. In a second changed unit replace the query key q by min(q,n), under the input contract 1≤q≤n. The new expression reaches the loop guard on every query, and the reset reaches the scan entry. A ranker crediting every changed upstream unit for reachable extra advances assigns both the same 28 excess advances at n=8. The entry-position account assigns the 28 to the reset. Independently reversing the clamp leaves 36 advances; reversing the reset restores eight. A value-sensitive baseline can also discover that the clamp changes no values. Include a version of the comparator that filters identical operand values on alignable events. If it eliminates the proposed benefit in development, freeze that stronger comparator as primary and reassess the hypothesis before test access. This construction establishes a distinction between two specified rules; only natural changes can establish that it matters in practice.

**Boundary of the proof.** With queries of decreasing rank, carrying the cursor can give a wrong answer. With all ranks zero, even a recurring reset adds zero advances. A write overwritten before loop entry contributes zero. For any finite maximum tested size M, a cost function can agree with n up to M and become quadratic thereafter. General asymptotic orders therefore require a semantic argument such as the one above. Experiments support statements about registered workloads, sizes and operations.

## 3. What the candidate would measure

1. **Establish a paired discrepancy.** Use a workload-owned measure with the same meaning on both revisions, such as successful advances through the same logical sequence. Record the input family, object identity, order and query shape. For the broader assessment use independent counts or uninstrumented timing as declared per task. A missing or zero denominator needs explicit handling. Keep raw counts and differences wherever a ratio is undefined.
2. **Account for the extra work.** For m aligned scans, let aⱼ and bⱼ be entry and exit positions. On a stable sequence with unit forward advances within each scan, visits counted as *advances* total F=Σ(bⱼ−aⱼ). Define R=Σⱼ₌₂ᵐ max(0,bⱼ₋₁−aⱼ) and J=Σⱼ₌₂ᵐ max(0,aⱼ−bⱼ₋₁). Telescoping gives **F=bₘ−a₁+R−J**. Subtract the reference identity from the target identity to distinguish differing endpoints, forward skips and rewinds. A large rewind alone can be legitimate. Check the accounted excess against an independently counted event and report the residual. Mixed object identities, invalidated positions, ambiguous alignment or unsupported step semantics require an explicit unsupported result.
3. **Attach a source explanation.** For a differing scan entry, follow executed reaching definitions, copies, loop-carried values and controlling branches to changed units. Kill overwritten definitions. Include anchored deletions when a reference-side update disappears. Give a changed unit evidence only for activations it can reach. Rank by excess backward distance on matched activations attributable to a single changed unit, summed over the largest common clean size and averaged across registered workload seeds. Preserve jointly attributable distance separately to avoid double counting. Abstain if no positive uniquely attributable distance survives or if first place ties. Emit the scan site, change span, path, units, observed counts and unassigned distance so a reviewer can check the explanation.
4. **Distinguish the three claims.** A charge accounts for trace events. A source path identifies an upstream candidate. A correctness-preserving intervention that removes the measured excess supports a contextual causal claim. The latter requires the independent procedure in section 5. It need not identify a unique cause. Report elapsed-time benefit only after independent uninstrumented measurements.

**Construction cost.** Once two ordered streams of scan episodes are aligned and carry stable object and query identities, the accounting step takes one pass over m episodes. It needs the previous exit and running totals per active sequence, plus one accumulator per attributed source unit. This establishes that a small demonstrator is producible. It gives no bound on the cost of collecting dynamic dependences, resolving C++ aliases or aligning different algorithms. Those costs belong in the feasibility study. For the first demonstrator, pair episodes by workload query ordinal, logical object and static scan site mapped between revisions. Reject missing, duplicated or ambiguous matches. Assess the frequencies of those failures over the full development draw.

**Competing explanations from the literature.** Trend-prof already models basic-block counts against workload size. Cody-Kenny and colleagues already locate infrequently executed performance-sensitive sites through mutation. PerfImpact already runs the same inputs on two versions and ranks changes by impact. A paper claiming any of those ideas as its contribution would duplicate prior work. [Trend-prof](https://theory.stanford.edu/~aiken/publications/papers/fse07.pdf) · [Performance Localisation](https://arxiv.org/abs/1603.01489) · [PerfImpact](https://doi.org/10.1145/2901739.2901765)

CLARITY detects redundant traversals and TODDLER detects repeating memory-access patterns across loop iterations. Loopus uses increments and resets to derive bounds. CLARITY's JFreeChart example gives a concrete boundary case: repeated recomputation of a per-series minimum can be fixed by reuse, even though the rank-query carry invariant does not describe that repair. EffiHolmes also connects workload-dependent hotspots to fix locations, at file/function granularity in Python. The proposed contribution lives or dies on the added diagnostic value of a quantitative, source-attributed account of *paired* excess work. It is also possible that ordinary change-impact analysis already supplies all the useful information. [CLARITY, Fig. 1](https://www.cs.utexas.edu/~lin/papers/pldi15.pdf) · [TODDLER](https://mir.cs.uiuc.edu/~marinov/publications/NistorETAL13Toddler.pdf) · [Loopus](https://arxiv.org/abs/1508.04958) · [EffiHolmes](https://arxiv.org/abs/2608.03558)

## 4. Experiments that could defeat the hypothesis

| Comparison | What it tests |
|---|---|
| Diff alone, with source order and expected uniform success 1/k for one accepted unit among k | How much the patch itself gives away. Use accepted count divided by k for multiple individually sufficient units. Give single-unit patches their own row. |
| Target hotspot and paired change in local count across sizes | Whether a profiler or size-dependent differential already identifies the change. Project each arm to the same changed-unit universe and publish unmapped symptoms. |
| Paired change-impact ranker, **primary comparator** | Use the same aligned traces and whole-source change list. Rank each changed unit by positive additional symptom advances reachable downstream over the same sizes/seeds as the candidate, without cursor-distance attribution. Disclose that this is a PerfImpact-inspired comparator on fixed workloads. Compare with the original tool only where its inputs and output granularity match. |
| Compiler-backed backward slice from the same symptom | Measure retention and number of units a reviewer must inspect. Cross the conventional and historical scoped candidate sets with the same neutral ranking policy, then hold candidates fixed and compare rankings. Reconcile LLVM debug locations to source spans, pin a working toolchain, and record failures for every arm. [LLVM DG](https://github.com/mchalupa/dg) |
| Last reaching definition of the entry cursor, plus a repeated-traversal detector | Test whether one simple rule solves the entire mechanism. Remove distance attribution and then transitive edges in separate ablations. Report the cases where either change alters the decision. If the simple rule matches the proposed method, credit it. |

Lock each ranking and tie rule before evaluation. On the primary Top-1 endpoint ties without a unique recommendation are abstentions for all algorithms. Report tie frequency and a secondary expected score under uniform tie breaking. Give baseline developers the same calibration cases and evidence budget. Report overhead and coverage both over the original draw and on mutually supported cases. Include a repeated-object-traversal rule motivated by TRAVIOLI on the C++ traces and identify the adaptation explicitly. Coz measures the effect of speeding up an executing line. PerfFuzz searches for an exposing workload. They become matched baselines only if the research question and output budget include those tasks. Spectrum-based fault localization applies where workload-level pass/fail labels vary and every arm can access them. [TRAVIOLI](https://rohan.padhye.org/files/travioli-icse17.pdf) · [Coz](https://www.usenix.org/conference/atc16/technical-sessions/presentation/curtsinger) · [PerfFuzz](https://people.eecs.berkeley.edu/~ksen/papers/perffuzz.pdf)

**Control panel.** Include a true carried-progress loss with both an at-symptom and an off-symptom edit, transitive copies, a conditional nested reset, a killed write, unrelated changed statements, and a required restart under nonmonotone queries. Include appropriate quadratic target/reference pairs, same-growth shams, equally sized workloads with different shapes, a genuine constant-factor slowdown, and a real slowdown caused by an unrelated mechanism. For a constant-factor slowdown the timing effect is real while the scaling-change label is negative. For the unrelated mechanism the slowdown is positive while a cursor explanation is wrong. Write both expected labels before collecting predictions. Use logarithmic and half-power changes to characterize sensitivity outside the original 0.70 slope rule. Avoid counting a mechanism family repeatedly through renaming, seeds or additional sizes.

## 5. Independent labels, measurements and denominators

**Sampling.** Build three ledgers. The archived and newly authored controlled cases establish mechanism correctness. Consecutive or seeded, problem-grouped PIE validation cases estimate contest-code feasibility. A separately drawn project-grouped patch sample estimates repository feasibility. For the desk pilot, draw one publicly inspectable development pair from each of 12 distinct PIE validation problems and one patch from each of 12 distinct development projects if available. Preselect by stable hash before reading outcomes. Record raw draw, pair orientation, alignment, change count, scalable inputs, oracle availability, anticipated label, human review time and explicit failure reason. These 24 are a proposed feasibility budget. All inspected projects/problems become development data. [PIE release](https://github.com/LearningOpt/pie) · [CppPerf-DB](https://arxiv.org/html/2605.10890v1)

**Measurement.** Before running a case, fix a correctness oracle, cost event, input generator, nuisance parameters, six geometrically spaced sizes and three independently generated shape-preserving workload streams where meaningful. Deterministic duplicate streams count once. For future execution, require at least four common uncapped sizes over an eightfold span, use the same inputs and a predeclared hardware/compiler configuration, and report every missing point. Do not fit a cap as a completed observation. Report right-censoring, sensitivity to dropping the largest size and the coverage lost to caps. Calibrate operation definitions against a separate counter and published closed forms where possible. Include early/late-hit library searches and multiple optimization levels. Unknown library calls need a calibrated counter or an unsupported disposition. For timing, use plain binaries, interleaved randomized version order, warmups, repeated runs and variability per size.

For an initial **large finite-range scaling** target, retain the historical independent timing screen as an explicit design choice: a log slow/reference time-ratio slope of at least 0.50 on every registered stream and a largest-size ratio of at least 1.50. Label count-confirmed but timing-unconfirmed cases separately. Define the corresponding count-based primary label on an independent common metric using the same numerical screen, with sensitivity analyses for smaller effects. Neither failing a positive threshold nor a timeout establishes a negative. For negative controls use proved same-order constructions or independently verified equivalence margins fixed from development noise. Mark undecidable observations unresolved. Freeze any revised threshold on disjoint development data with a scientific rationale.

**Intervention oracle.** Two C++ reviewers independently receive the pair, specification, workload and oracle. Each identifies a minimal changed unit or set, predicts the affected work and explains why restoring it preserves outputs. They see no candidate rankings, attributed distances, or each other's labels. Revert that unit alone in the target when feasible. Validate outputs on registered and independent challenge inputs, independently recount cost, and revert a plausible inert unit as a sham where one exists. For the controlled family demand the exact predicted counts. For real cases preregister sufficient recovery, initially at least 80% of positive excess independent count at the largest two common sizes for every stream. Record partial recovery and the full ratio. Tests establish correctness on the tested domain, with stronger equivalence claims requiring a proof. A third reviewer adjudicates disagreements before scoring. Seal original votes, span mappings, intervention receipts, agreement and unresolved dispositions.

**Keep the reference independent of the method.** Choose each problem's cost oracle and registered workload using its specification and input contract before seeing a predicted symptom. Keep independent counting builds, challenge streams, reviewer judgments and intervention measurements on the evaluation side. The predictor uses its own traces. Record the prediction of a comparative discrepancy and the proposed cause separately. Score false discrepancy alerts on known negatives, wrong causal recommendations on confirmed slowdowns, and abstentions on both. This prevents a method from obtaining credit for detecting a slowdown simply because the evaluator handed it the positive label.

**Interactions.** Two independently sufficient alternative edits give a set of acceptable single recommendations. Two jointly necessary edits give a distinct multi-edit task, scored for complete-set recovery and reported separately. Whole rewrites without an isolatable change remain in the intake ledger. A patch by itself is evidence of intent. Agent judgments can suggest development cases, while independent humans and interventions establish evaluation labels.

**Statistics.** Freeze one source population and one primary comparator. From each independent group, use a prespecified representative multi-unit pair for the binary first-inspection comparison. Use a stable hash to choose among qualifying independently labeled cases before inspecting predictions. Compute paired win/loss/tie counts, absolute success difference, a 95% matched-pair score interval and an exact two-sided McNemar test at 5%. Give each group equal weight. For secondary all-pair estimates resample groups intact. Report all-draw coverage, unresolved fractions, conditional candidate recall, slice size, end-to-end Top-1, Top-2 and number of units inspected. Method failures, abstentions, missed detections or unmapped method outputs count as misses for confirmed, labelable positives. For confirmed positives with unresolved locations show pessimistic and optimistic success bounds. Report appropriate-control false alerts with their own denominator and interval. Stratify by cause at/away from the symptom, support, and number of changed units. Treat additional contrasts as exploratory.

**Power and acquisition reality.** The public PIE metadata list 978 test pairs from 41 problems. The frozen draw has 137 distinct-slow pairs in at most 35 connected groups. An earlier development-overlap sensitivity reduced that ceiling to 29. CppPerf has 347 patches from 42 projects. Its authors report an existing test demonstrating a significant timing improvement for only 35 patches. Neither inventory establishes enough independently attributable scaling changes. Keep project patches, contest solutions and authored families as separate populations. [PIE draw](../artifacts/phase2_data/README.md) · [Overlap analysis](../AUDIT.md) · [CppPerf, §3](https://arxiv.org/html/2605.10890v1)

For a transparent planning scenario assume the candidate alone succeeds on 27% of independent pairs and the comparator alone on 7%. The true advantage is 20 percentage points and discordance is 34%. Condition on the discordant count D, which is binomial with parameters n and 0.34. Under the alternative the number of wins given D is binomial with parameters D and 27/34. Summing the probability of the exact two-sided 5% rejection region gives 43.3% power at 35 groups, 72.7% at 60, 80.5% at 71 and 85.5% at 80. These figures describe this design only. With zero false alerts, 29 independent negative controls give a one-sided 95% upper bound of 9.8%; ten give 25.9%. Recalculate with the pilot's eligibility, uncertainty in discordance, group mergers, annotation attrition and jointly required gates. A 60-family or 20-group historical floor alone does not size this study.

**Decision rule.** Before registration, define a practically worthwhile effect with the intended users. Use 20 percentage points as the planning alternative until then. A powered superiority claim requires positive effect, a paired interval excluding zero and the registered test passing. A claim that the gain exceeds a particular practical margin requires the interval's lower bound to exceed that margin. A low-false-alert claim requires its own prespecified upper bound and enough independent controls. Report conditional estimates and intervals even if the protocol yields a null, an under-sized cohort or an inconclusive result.

**Manuscript path.** Lead with the identifiability result and a natural failure case. Follow with the operational question, the worked proof, the prior-art comparison, the independently labeled study, and the full flow of exclusions. A sufficient human sample and a win over the prespecified competitive comparator support a bounded localization claim. A strong accounting result with few natural examples supports a mechanism study and case series. If a simpler baseline ties, present the diagnostic and benchmark evidence; retire the extra ranking machinery. If labels or workloads cannot be produced independently, publish the feasibility constraints and defer an effectiveness paper.

**Current judgment.** The mechanism and the limitations are provable on paper. The old artifact supplies working measurements, counterexamples and a credible starting point for reproduction. The largest open risk is finding enough independent human changes for which a fair competitor has more than one plausible choice and an intervention supplies a verifiable answer. Measure that yield before building a general C++ analyzer or training another model.
