# Prospective synthetic evaluation of EAPG

**Version 0.5.0 · Protocol Specification · 16 November 2026**

> **Execution Status (17 November 2026):** Bounded 10-family multi-agent execution completed in [`prospective_multiagent_results.json`](prospective_multiagent_results.json) (`primary_sized = false`, `10 < 60` required families; `280` placeholder-quarantined slots alongside `0` real collisions across `101` pilot+PIE exposure rows). See [`../docs/INDEPENDENT_AUDIT.md`](../docs/INDEPENDENT_AUDIT.md).

This protocol defines a proposed C++17 benchmark of planted, reversible growth interventions. Its primary question is whether scoped slicing improves Top-1 localization over a conventional backward slice given the same work symptom. The work-weighting comparison, alert behavior, and ranker comparisons address separate outcomes. The population is fresh authored problem and generator families under registered workloads. The published synthetic pilot, existing authored fixtures, and previously inspected human-written case supply development evidence. The PIE test draw remains sealed under the [Phase 2 decision](../PHASE2_DECISION.md).

The benchmark uses independent measurements because node hits, estimated node work, whole-program algorithmic operation counts, and wall time represent different quantities. Workload and comparison specifications, raw observations, failure dispositions, and clean-environment replication commands are part of the benchmark package. [ACM SIGSOFT Benchmarking standard](https://raw.githubusercontent.com/acmsigsoft/EmpiricalStandards/master/docs/standards/Benchmarking.md) · [TrendProf](https://theory.stanford.edu/~aiken/publications/papers/fse07.pdf) · [Algorithmic Profiling](https://sape.inf.usi.ch/publications/pldi12)

## Frame, workloads, and intervention reference

Before collecting outcomes, register a complete frame and the draw procedure. An independently maintained frame identifies each problem, specification, implementation origin, generator and ancestors, proposed intervention mechanism, and positive/control slots. Draw 80 origin families without replacement, using a registered randomization seed within predeclared mechanism strata. Seal the ordered frame, allocation, and all drawn IDs. Register one intended off-site positive, one intended at-site positive, one same-growth sham, and one appropriate superlinear control per drawn family. For the off-site slot, register a costly statement that the edit is expected to affect and an edit span disjoint from that statement. This is an author-design stratum. Determine disagreement with the method's actual symptom separately. Balance sham slots across baseline growth classes, including superlinear shams, and preassign near-threshold positives across at least two mechanism strata. The frame must specify counts and allocation rules for these slots before sampling. Several rewrites of the same implementation or generator count as one family.

The [frame validator and draw utility](synthetic_frame.py) checks the four core slots per origin, the allocation, sham-class balance within one slot, and the two near-threshold bands. It replays the fixed quotas by hashing the seed and frame positions within each registered allocation cell. The comparator swap occupies two separately registered diagnostic slots outside the core draw. Store an independent protocol and frame digest before selection. Bind the selected workloads to their ordered input-byte digests before execution. Verify the saved selection and draw byte-for-byte with the original pins. This tool has been exercised with an authored mock frame.

Each family registers a valid input distribution, three generator seeds (`42`, `43`, `44`), and six sizes `N0 × 2^j` for `j = 0,…,5`. The frame gives `N0` and explains how each other size parameter varies with `N` or stays fixed. Author all slots within the C++17 subset registered for both slicing methods. Use the same input bytes for the original, edited and restored programs and for all profilers and comparators. Seal every generated input digest before the first test execution. The reference panel covers positive operation counts under polynomial or polynomial-times-logarithmic growth. Report fitted slopes as finite-range summaries.

Before locking the frame, use the [source-domain preflight](audit_synthetic_frame_domain.py) on every proposed slot and both comparator-swap cases. It binds the complete source inventory to the frame before checking C++17 syntax, the registered normalizer, and reachability in the conventional CFG. Keep the receipt for the locked version and record source-domain exclusions from earlier proposals. The role counts help diagnose canonical criteria coverage. The independent oracle, reference mapping, and observed symptom check still determine case dispositions after the draw. During this preflight, keep program output, fit, and localization results out of frame selection. An intervention author records one contiguous source edit within one expression or statement, with a nonempty changed token span in the edited source. The record contains the original, edited and restored raw source hashes, raw byte offsets and bytes on both sides of the edit, forward and inverse patches, expected output relation, operation mechanism, and any intended costly statement. An independent verifier checks that applying the forward patch reproduces the edited bytes and applying the inverse reproduces the original bytes exactly. The verifier checks the raw edit site, allowable alternative intervals, and the operation argument before seeing any EAPG output. Every alternative interval must identify the same intervention in the raw source. Freeze the reviewer decisions and patches before normalizing or profiling evaluation cases.

Map the accepted raw intervals through the pinned source-origin map into normalized source. Use half-open UTF-8 byte offsets and map each interval to the smallest canonical macro-node containing all its changed nontrivia tokens. The map records normalized-source digest, node IDs, owned spans, and raw origins. A unique shortest covering node yields a reference ID. Take the union for independently accepted equivalent raw intervals. No covering node, nonunique expansion, or tied minimal owners without a precommitted equivalent mapping yields `unresolved_reference`. Keep the raw intervals and mapping evidence for replay. Use this same normalized source and canonical node universe in every arm. Mapping and adjudication must finish before any prediction is visible to the verifier.

The [exact token mapper](synthetic_intervention.py) verifies the source commitments, the forward and inverse splice, and the changed tokens' statement or expression ownership. It traces the ordered raw token stream to preprocessing output and records original byte positions through synthetic brace insertion. This implementation resolves files whose preprocessing preserves the ordered nontrivia token stream, ignoring unchanged includes. It records a reason and retains the normalized node universe on unsupported expansions or ambiguous canonical ownership. Equivalent intervals must select the same changed tokens through this mapper. Register this mapping domain and any independently adjudicated alternative mapping before locking the study.

## Independent oracle and case dispositions

For each slot, register an independently implemented output oracle derived from the task specification and a whole-workload operation inventory. The inventory defines the unit-cost operations and their scope, including input/output item processing, setup, and the affected computation. It must account for every growth-bearing stage and use identical units across the original, edited and restored versions. Register a closed-form count or recurrence derived from the workload and a separately implemented counting build or trace of those operations. The verifier checks the inventory against the source and confirms exact per-input agreement between the counting build and the formula. C++ instrumentation used for these checks is separate from EAPG's instrumented binary, fit and container-size weights.

The [operation eligibility checker](synthetic_oracle.py) verifies the registered outputs and counts through separate isolated plain, sanitizer, and counting builds. It records exact per-run evidence, checks restored counts against the original, and applies the growth bands per seed. The independent verifier remains responsible for the count inventory, analytic growth argument, and construction of the expected answers from the task specification.

For a valid case, all three plain programs and all oracle-count builds must complete with the expected output on the full grid, including under the registered sanitizer check for plain programs. Check exact restoration of whole-workload counts at each input. For each seed fit the unrounded OLS slope `d` of `log(W_edited / W_original)` against `log(N)` on all six sizes. Register the expected analytic growth classes and a numeric band per slot, then apply these panel rules on every seed.

| Slot | Verification rule | Expected alert for the planted-edit task |
| --- | --- | --- |
| Strong positive | An independently justified higher growth order, `d >= 0.70` and largest-size operation ratio `>= 1.50`. | Alert |
| Near-threshold positive | A justified higher growth order, largest-size operation ratio `>= 1.50`, and the preassigned band `[0.55, 0.70)` or `[0.70, 0.85]`. Register cases on both sides. This band refers to the oracle slope. | Alert |
| Same-growth sham | One reversible edit, analytically the same growth order, and `abs(d) <= 0.10`. A constant-factor change is permitted. | No alert |
| Appropriate superlinear control | The specification calls for the high-growth work, such as enumerating every pair. Independently derive its superlinear count and verify the observed counts. Register identical original and evaluated bytes for this slot. | No alert |

Precommit intended slots before generating or running the draw. Keep a failed positive in its intended stratum with its reason. A failed positive never becomes a control. Record per-run output, compiler/sanitizer/transport status, wall time, operation counts, and any censoring. Use a terminal disposition per slot for quarantined provenance, invalid source or input, failed semantic/output/sanitizer check, missing or failed operation validation, failed growth criterion, or independently confirmed positive/control. Preserve earlier stage evidence and multiple failure reasons. Reference resolution, profiling, and prediction are subsequent dispositions. A confirmed positive with unresolved mapping remains a confirmed positive.

## Estimands, sizing, and decision

The primary denominator is all independently confirmed, provenance-eligible positives on the draw, including unresolved references and downstream failures. A Top-1 hit is the first predicted canonical node in the accepted set. An unresolved reference, absent symptom, unavailable fit, empty slice, transport failure, invalid prediction, or abstention contributes zero for the affected arm. For each final family, average paired binary differences (`work-scoped − work-conventional`) over its primary cases. Average those family means with equal weight. Report per-arm equal-family and case-weighted rates, the paired contrast, both directions of discordance, and a two-sided 95% percentile interval from 10,000 resamples of entire final families with replacement (seed `42`, nearest-rank endpoints). Report leave-one-family-out contrasts, mapping-resolved rates, and missing-reference and intention-to-test bounds. For an upper bound on each arm, count unresolved cases with valid predictions as potential hits. For the contrast, take the minimum and maximum differences over admissible hit assignments, keeping identical predictions tied and recorded abstentions as zeros. Give an intention-to-test sensitivity over all intended positive slots, treating unconfirmed and quarantined slots as misses for both arms and preserving final component weights wherever known.

Prespecify the shared-work symptom-disagreement subset as resolved positives where the primary-seed work symptom exists and is outside the accepted set. Use the two work-slice arms for its paired contrast. The work symptom-alone rate is zero by construction in this subset. Report represented families, uncertainty, and leave-one-family-out sensitivity. Also report end-to-end performance on the author-design off-site stratum, including cases without a symptom. The author stratum and observed disagreement answer different questions. An affirmative away-from-symptom claim requires the primary gate and a lower 95% interval endpoint above zero for the same-work contrast in the observed disagreement subset with at least 30 represented families. Evaluate these gates in that order. Report the estimate and interval descriptively if the second gate lacks support.

Size the core study for an absolute `0.20` improvement in family-weighted Top-1. With two-sided `α = 0.05`, 80% nominal power and assumed family-level variance `0.30`, a normal approximation gives `ceil((1.96 + 0.84)^2 × 0.30 / 0.20^2) = 59` independent families. For each family's paired binary differences, average case discordance bounds the squared family mean by Jensen's inequality. An expected discordance no greater than `0.30` is sufficient for the variance to be no greater than `0.30`. The variance is a planning assumption because the retrospective pilot compares different methods and has few off-symptom families. Variance `0.20`, `0.40`, and `1.00` would require about 40, 79, and 196 families respectively. Target at least 60 independently confirmed positive families from the fixed draw of 80. The 20-family allowance covers merges and screening losses. Report achieved discordance and interval width without updating the target. A positive primary result requires at least 60 represented families and a lower 95% endpoint above zero. The `0.20` planning effect describes design sensitivity. Report the actual estimate and interval.

The [pre-data sensitivity calculation](plan_synthetic_power.py) enumerates the ideal percentile-bootstrap gate under an independent ternary model for family differences. It assumes that the two qualifying slots within a family have the same paired difference and that family retention is independent of outcome. For a true difference of `0.20`, family discordance `0.34` gives variance `0.30`. At 60 retained families, the ideal gate has 78.64% power. At 80, it has 88.97%. With 80 drawn and independent retention of 75%, 80%, or 85%, the probabilities of reaching 60 families are 55.97%, 89.34%, and 99.37%. The corresponding probabilities of passing the full primary gate are 44.91%, 72.64%, and 82.56%. These values are design sensitivities under stated assumptions. The calculation approximates the registered finite-resample gate and leaves its thresholds unchanged.

Publish the full flow from drawn slots and components through eligibility, confirmed class, reference resolution, completed profiles, symptom availability, candidate count, reference retention, and prediction. Report alerts and abstentions separately. On confirmed positives, give sensitivity with unobserved alerts counted as misses. On each confirmed control class, give observed alerts over the full denominator, with a bound counting all unavailable results as possible alerts, and give coverage. Report each arm's candidate count, reference retention and reduction `1 − |candidates| / |canonical universe|` when a slice is emitted. Include full-denominator retention with unavailable slices as misses. Give conditional diagnostics with their counts and family counts. Use equal-family summaries for paired outcomes and show case counts for reproducibility. Secondary estimates outside the ordered primary and off-symptom gates are descriptive.

Measure uninstrumented timing separately. The full 320-slot draw would require 57,600 timed invocations before calibration and retries. If that exceeds the measured execution budget, predeclare a stratified timing panel and its allocation before drawing the main cohort. On the pinned host and compiler, use five fresh invocations per side, seed, and size, with one registered permutation of run order and a protected monotonic clock. Record hardware, software, limits, flags, startup/no-op distribution, measurement boundary, raw repeats and failures. For complete grids, divide the median edited time by the median restored time at each size and fit the log-ratio slope against log size. Report completion and censoring across the timing panel. Timing stays descriptive and outside primary eligibility. [Kalibera and Jones, Rigorous Benchmarking in Reasonable Time](https://kar.kent.ac.uk/33611/)

## Lock and execution gates

1. Validate the oracle, inverse, source mapping, quarantine, both slicing implementations, fit rules, and ledger join using authored development fixtures. Exercise no symptom, empty slice, scope-sensitive receiver/call resolution, fit/cap and normalization failures, and, if applicable, actual tokenization and overflow. Verify that no prediction leaks labels and that removing a bridge row leaves the sealed component intact. Pin the dry-run command and expected output.
2. Before drawing, pin the exact frame and slot allocation, role and access assignments, oracle/workload and provenance rules, execution budget, compiler and sandbox image, candidate and baseline source digests, emitted-slice prediction path, analysis/scorer, and replication commands. Freeze all decisions and thresholds. Record the resource and personnel commitments. This draft becomes a registration only when these artifacts and the signed protocol digest exist.
3. Seal the draw, raw interventions, labels, and quarantine as specified. If the required frame, independent verifier, isolation, provenance, or implementation is unavailable, record the gate as infeasible. If fewer than 60 independent confirmed positive families remain after the fixed draw, record the primary analysis as under-sized and descriptive. Keep the original draw and dispositions. Changes motivated by evaluation outcomes require a new version and fresh disjoint families. Refit, threshold changes, replacements, and added draws are outside this registration.
4. After prediction commitments, score from the outer join over the frozen draw. Reject duplicate or unexpected IDs, digest or node-map mismatches, reference leaks and missing disposition records. Publish permitted artifacts and a table-to-revision manifest with commands that regenerate a fresh authored profile and replay every released table. Label saved-result replay and any independently rerun executions separately.

This draft leaves the final frame, independent personnel and attestations, registered manifests, software and runtime pins, and qualifying family count pending. The runbook defines the authored end-to-end check. This draft contains no prospective results.
